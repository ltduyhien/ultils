### SLIDE 2: SYSTEM OVERVIEW - ENHANCED
- Network-transparent and vendor-neutral monitoring system designed for operator-scale infrastructure
- Combines network monitoring and reporting under one unified environment
- Serves both network planning units and network monitoring/operations teams
- Key statistics:
  - Over 2,500,000 indicator statistics updated every 180 seconds
  - Over 1,000,000 lines of CSV-formatted inventory data processed nightly
  - Approximately 5,000 devices monitored with over 4,200 active monitoring points
  - 140,000 enabled objects and 1,400,000 disabled objects in SevOne database
  - 171,000 object licenses with 1.50 USD per license cost (before discounts)
  - Over 100,000 lines of custom code developed by Telia and Tietoevry over 3+ years
  - 1,800 Qlik reporting groups containing 18,000 monitored objects
  - 200,000+ objects distributed across 4 collector peers
- System characteristics:
  - Fully automated end-to-end workflow from input to output
  - No constant manual interactions required in normal operations
  - High reliability with critical issues occurring only once every 2 years
  - Non-critical issues occurring once every 6 months
  - Provisioning issues occurring approximately once per month
  - Typical device provisioning time: 5-15 minutes depending on configuration

### SLIDE 9: PROVISIONING OVERVIEW - ENHANCED
- Fully automated device provisioning process
- Based on Generic Device Role classification
- Four-phase provisioning workflow
- Integration with SurfManager/Operator (SM/O)
- Trigger phase: Device added to SM/O, port check initiated, role assignment, rulebook evaluation, CSV generation, file transfer
- Noora phases: Loader (validation/discovery), Pinning (registration/SNMP), Discovery (object enablement), Link (link objects)
- Post-provisioning: Alarm policy application, threshold monitoring, reporting group assignment, data export configuration
- Characteristics: No manual intervention normally, rulebook-driven, error handling, comprehensive logging, 5-15 minute completion, exceptional cases may need intervention

### SLIDE 10: SM/O PROVISIONING PHASES - ENHANCED
- Phase 1: Port Check
  - Assigns Generic Device Role
  - Determines if Noora monitoring should be enabled
  - Rulebook-controlled by Tela
  - Device identification and metadata retrieval
  - Role assignment process (Managed/UnManaged/Unrecognized)
  - Noora monitoring eligibility check
  - Port selection for monitoring
  - CSV file generation (device_record.csv + instructions)
- Phase 2: Device Provisioning
  - Checks if SevOne monitoring should be enabled
  - Uses Noora provisioning rulebook
  - Eligibility verification process
  - Decision points and exception handling
  - Provisioning initiation and queue management
- Phase 3: Port Provisioning
  - Selects ports for monitoring
  - Based on Generic Device Role and monitoring requirements
  - SM/O Link identification and verification
  - Port configuration and metadata enrichment
  - Port description field population (<deviceB> <portId> <speed>)

### SLIDE 11: NOORA PROVISIONING PHASES - ENHANCED
- Phase 1: Loader
  - Receives CSV files from SM/O (data + instruction)
  - Checks device eligibility
  - Verifies device reachability
  - Triggers SevOne discovery
  - CSV file reception and processing
  - File validation and integrity checks
  - Backup creation and error handling
  - Device eligibility verification
  - Reachability testing (ICMP, SNMP, port accessibility)
- Phase 2: Pinning
  - Determines device type
  - Checks SevOne registration
  - Sets supported SNMP object types
  - Device type determination (SNMP sysObjectID)
  - Registration status verification
  - Duplicate device detection
  - SNMP object capability assessment
  - Object configuration in SevOne
- Phase 3: Discovery
  - Enables discovered objects
  - Hardware objects (CPU, memory, fans, power supplies)
  - Port objects with SM/O metadata
  - Additional objects (COS queues, service interfaces)
  - Hardware object enablement (CPU, memory, PSU, fans, sensors)
  - Interface object enablement (physical, logical, virtual, aggregated)
  - Service object enablement (COS queues, service interfaces)
  - SM/O instruction processing and metadata enrichment
- Phase 4: Link
  - Builds link objects in SevOne
  - Prevents historical data interruption during port migrations
  - Rulebook-based for backbone network ports
  - Link object creation for historical continuity
  - SM/O link identification and end port verification
  - Calculated object creation and statistics copying
  - Link object management and reporting
