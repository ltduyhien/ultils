## Slide 3: Noora Application Summary

### Overview
Noora is a comprehensive network monitoring and management system designed to ensure the reliability, performance, and security of Telia's network infrastructure. It integrates with various systems, including SurfManager&Operator (SM/O), SevOne, and Neli, to provide a unified monitoring and management platform.

### Key Features
- **Device Monitoring**: Noora monitors a wide range of network devices, including routers, switches, load balancers, and firewalls.
- **Performance Metrics**: Collects and analyzes performance metrics such as CPU usage, memory utilization, and network traffic.
- **Alert Management**: Generates and manages alerts based on predefined thresholds and policies.
- **Reporting**: Provides comprehensive reporting capabilities for network performance, capacity planning, and troubleshooting.
- **Integration**: Integrates with external systems such as SM/O for device provisioning and Neli for alert management.

### Architecture
- **Dual Data Center Architecture**: Noora operates in a dual data center setup, ensuring high availability and redundancy.
- **Modular Design**: The system is designed with modular components, allowing for easy scalability and maintenance.
- **API-Driven Integration**: Noora uses APIs to integrate with external systems, ensuring seamless data flow and interoperability.

### Technologies
- **SevOne**: Noora is built on top of the SevOne Network Management System, leveraging its monitoring and reporting capabilities.
- **SM/O**: SurfManager&Operator is used for device provisioning and management.
- **Neli**: Network Element Interface (Neli) is used for alert management and notification.
- **Database**: Noora uses a robust database system to store and manage network performance data.

## Slide 4: Noora - High Level

### Provisioning Data Flow
Noora's provisioning process is a multi-phase workflow that ensures devices are correctly configured and monitored. The process involves the following key steps:

1. **SM/O Port Check**: The Port Check function in SM/O assigns a Generic Device Role to the device and checks whether the device should be enabled for Noora monitoring.
2. **Device Provisioning**: SM/O verifies whether the device should be provisioned in Noora and enables monitoring based on the Generic Device Role.
3. **Port Provisioning**: SM/O checks the need for port monitoring and enables ports based on the device's role and monitoring requirements.
4. **Noora Loader**: Noora's provisioning machine receives the device data and instruction files from SM/O and checks the device's reachability.
5. **Noora Pinning**: The device's type is determined, and it is checked whether the device is already registered in SevOne.
6. **Noora Discovery**: All objects found during the SevOne discovery are registered, and SNMP objects are enabled based on the device's role.
7. **Noora Link**: Link objects are built in the SevOne system to prevent the interruption of historical data during port migrations.

### Polling
Noora uses SNMP polling to collect performance data from network devices. The polling process involves:

- **SNMP Configuration**: Devices are configured with SNMP settings to allow Noora to collect performance metrics.
- **Data Collection**: Noora collects data such as CPU usage, memory utilization, and network traffic from the devices.
- **Data Processing**: The collected data is processed and stored in Noora's database for analysis and reporting.

### Data Pipeline
Noora's data pipeline ensures that performance data is collected, processed, and stored efficiently. The pipeline includes:

- **Data Ingestion**: Performance data is ingested from network devices using SNMP polling.
- **Data Processing**: The ingested data is processed to extract relevant metrics and insights.
- **Data Storage**: Processed data is stored in Noora's database for historical analysis and reporting.
- **Data Visualization**: Stored data is visualized through dashboards and reports, providing insights into network performance and health.

## Slide 7: System Architecture & Design

### Dual Data Center Architecture
Noora operates in a dual data center setup, ensuring high availability and redundancy. The dual data center architecture provides the following benefits:

- **High Availability**: Ensures that the Noora system is always available, even in the event of a data center failure.
- **Redundancy**: Provides redundant components and data storage to prevent data loss and ensure continuous operation.
- **Load Balancing**: Distributes the workload across multiple data centers to optimize performance and resource utilization.

### Monitoring Protocol
Noora uses SNMP (Simple Network Management Protocol) for network metrics collection. SNMP provides the following capabilities:

- **Data Collection**: Collects performance data from network devices, including CPU usage, memory utilization, and network traffic.
- **Alert Generation**: Generates alerts based on predefined thresholds and policies.
- **Data Visualization**: Provides real-time visualization of network performance metrics through dashboards and reports.

### Supported Devices
Noora supports a wide range of network devices, including:

- **Routers**: Monitors and manages router performance and configuration.
- **Switches**: Monitors and manages switch performance and configuration.
- **Load Balancers**: Monitors and manages load balancer performance and configuration.
- **Firewalls**: Monitors and manages firewall performance and configuration.
- **Proxies**: Monitors and manages proxy performance and configuration.
- **SAN Switches**: Monitors and manages SAN switch performance and configuration.

### Virtual Appliances
Noora is deployed on VMware virtual appliances, providing the following benefits:

- **Scalability**: Allows for easy scaling of Noora components to meet growing network demands.
- **Flexibility**: Provides flexibility in deploying and managing Noora components across different environments.
- **Efficiency**: Optimizes resource utilization and reduces operational costs.

## Slide 15: Noora Daily Health Check Protocol at A Glance

### Overview
The Daily Health Check (DHC) protocol outlines the steps for performing a daily health check on the Noora system. The goal is to ensure that the system is operational, alerts are functioning, capacity is stable, and server resources are monitored.

### Steps
1. **Login**: Log in to Noora using the Authentication System (Organization Central Authentication Directory).
2. **Cluster Manager**: Navigate to the Cluster Manager to verify the number of devices and check the overall capacity.
3. **Alerts**: Verify that alerts are flowing in and check the timestamp of the topmost/latest alert to ensure it is recent.
4. **Device Managers**: Open the Device Manager to check for any changes in devices or configurations.
5. **Reports**: Navigate to the Report Manager to verify that favorite reports are accessible and their graphs are functioning correctly.
6. **User Provisioning**: Check emails and the User Management System for any new user provisioning requests.
7. **Check, Verify, and Investigate**: Search for specific devices by name, click on the device summary, and test device settings by performing an SNMP walk function.
8. **Escalation Procedures**: Escalate issues to the Resource Manager (RM) if necessary, following the Organization's process for creating problem and incident tickets.
9. **Documentation**: Document any anomalies or issues encountered during the health check and ensure all steps are logged for future reference.

## Slide 17: Noora Daily Health Check Protocol (Continued)

### Check, Verify, and Investigate
- **Device Search**: Search for specific devices by name and click on the device summary to view detailed information.
- **SNMP Walk**: Test device settings by performing an SNMP walk function to verify device activity and SNMP polling.
- **Error Messages**: Regularly check for admin error messages and investigate new alerts as needed.
- **Server Access**: Use SSH to access the Noora servers with users created specifically for troubleshooting.
- **Disk Space**: Check disk space for critical partitions to ensure sufficient storage capacity.
- **Server OS**: Verify server OS details using commands like `cat /etc/os-release`.

### Escalation Procedures
- **Issue Identification**: Identify issues such as missing data, alert failures, and disk space issues.
- **Escalation**: Escalate identified issues to the Resource Manager (RM) for resolution.
- **Screenshot Capture**: For cluster issues, take screenshots (ensuring confidentiality) and inform the RM.
- **Incident Ticket Creation**: Follow the Organization's process for creating problem and incident tickets.
