Noora Shadow Sessions - Incidents Integration Analysis

This document provides an analysis of the incidents mentioned in the shadow sessions, their root causes based on the Noora integration and provisioning process, and detailed resolution steps. The analysis is based on the Noora device provisioning process documented in `materials/noora_provisioning_docs.txt`.

=== Integration Overview ===

Noora's device provisioning automation is based on the Generic Device Role classification managed by SurfManager&Operator (SM/O). The process involves four phases in SM/O and four phases in Noora, followed by alarm configuration in SevOne. The integration ensures that devices are correctly provisioned, monitored, and that alerts are generated and forwarded to Neli.

=== Incident Analysis and Resolution ===

1. Missing or Corrupted Data from External Sources
   - Root Cause:
     - Issues in the CSV files generated by SM/O during the Port Check phase.
     - Errors in the data file or instruction file sent to Noora.
     - Parsing errors in Noora's provisioning machine during Phase 1 (Loader).
   - Integration Impact:
     - Incorrect or missing data in the CSV files can lead to failures in Noora's provisioning phases.
     - Parsing errors can interrupt the provisioning process, leading to devices not being provisioned correctly.
   - Resolution Steps:
     - Identify the specific CSV file causing the issue in the External Data tab.
     - SSH into the ferguson server and navigate to the CSV file location.
     - Apply hot fixes to the CSV file to correct formatting issues.
     - Monitor the provisioning engine status to ensure the fix is applied correctly.
     - Verify that the data parsing status changes to "OK" after the fix.
   - Reference: shadow3_noora.txt, kt3_noora.txt, materials/noora_provisioning_docs.txt

2. Broken Links Reported by Users
   - Root Cause:
     - Incorrect link configuration in SM/O during the Port Provisioning phase.
     - Errors in the instruction file sent to Noora, leading to incorrect link objects.
     - Issues in Noora's Phase 4 (Link) where link objects are built in SevOne.
   - Integration Impact:
     - Broken links can disrupt network monitoring and reporting.
     - Incorrect link objects can lead to historical data interruption during port migrations.
   - Resolution Steps:
     - Use the Object Manager to search for the specific device and link.
     - Check the Calculation Editor for link expressions and verify their correctness.
     - Preserve link history by keeping the link with the correct expression.
     - Delete duplicate or incorrect links to resolve conflicts.
     - Verify link functionality by checking the graph and data flow after fixes.
   - Reference: shadow3_noora.txt, kt5_noora.txt, materials/noora_provisioning_docs.txt

3. Device Provisioning Issues
   - Root Cause:
     - Devices not being reachable during Noora's Phase 1 (Loader).
     - Devices not being registered in SevOne during Noora's Phase 2 (Pinning).
     - Incorrect SNMP object types being set for the device.
   - Integration Impact:
     - Unreachable devices can interrupt the provisioning process.
     - Unregistered devices can lead to missing monitoring data.
     - Incorrect SNMP object types can result in incomplete data collection.
   - Resolution Steps:
     - Use the Device Dashboard to check the status of the device.
     - Verify SNMP responsiveness and pooling status for the device.
     - Check the Device Summary for alerts and hardware status.
     - Investigate missing data and corrupted metadata using system logs.
     - Contact Kurt or Kevin for hardware-related issues that require further investigation.
   - Reference: shadow3_noora.txt, kt3_noora.txt, materials/noora_provisioning_docs.txt

4. Nelli Integration Issues
   - Root Cause:
     - Incorrect alarm policy configuration in SevOne.
     - Issues in the SNMPTRAP forwarding to Neli.
     - Errors in the debug level messages sent to Nelli.
   - Integration Impact:
     - Failed debug level messages can disrupt the integration between SevOne and Nelli.
     - Incorrect alarm policies can lead to missing or incorrect alerts.
     - Issues in SNMPTRAP forwarding can result in alerts not being received by Neli.
   - Resolution Steps:
     - Check the integration between SevOne and Nelli using the Nelli Pulse debug messages.
     - Verify that the debug messages are being sent and received correctly.
     - Contact the Nelli team for escalation if the integration issue persists.
     - Improve communication with Nelli to ensure timely updates and resolutions.
   - Reference: shadow9_noora.txt, kt8_noora.txt, materials/noora_provisioning_docs.txt

5. Stuck Phase 2 Devices
   - Root Cause:
     - Devices not being registered in SevOne during Noora's Phase 2 (Pinning).
     - Incorrect SNMP object types being set for the device.
     - Issues in the SevOne discovery process.
   - Integration Impact:
     - Unregistered devices can lead to missing monitoring data.
     - Incorrect SNMP object types can result in incomplete data collection.
     - Issues in the SevOne discovery process can disrupt the provisioning flow.
   - Resolution Steps:
     - Kurt checks the SMO and provisioning status for the device.
     - Delete the device from the Device Discovery to reset the provisioning process.
     - Trigger a new provisioning process for the device.
     - Monitor the provisioning engine to ensure the device moves through the phases correctly.
   - Reference: shadow8_noora.txt, kt6_noora.txt, materials/noora_provisioning_docs.txt

7. Server Boot Issues
   - Root Cause:
     - Unscheduled boot of Noora causing provisioning scripts to fail.
     - Previous processes not being killed, causing conflicts.
     - Issues in the fail-safe processes for running scripts after a boot.
   - Integration Impact:
     - Failed provisioning scripts can disrupt the provisioning process.
     - Conflicts in processes can lead to missing or incorrect data.
     - Issues in fail-safe processes can result in incomplete provisioning.
   - Resolution Steps:
     - Ensure that the provisioning scripts run after the boot.
     - Kill previous processes to resolve conflicts.
     - Start new processes to ensure the provisioning engine functions correctly.
     - Follow fail-safe processes for running scripts after a boot.
   - Reference: shadow9_noora.txt, kt4_noora.txt, materials/noora_provisioning_docs.txt
