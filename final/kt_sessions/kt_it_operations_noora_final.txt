=== SYSTEM OVERVIEW ===

Q1. What is SevOneDDC and its relationship to Noora?
A1. SevOneDDC is a comprehensive network monitoring platform specifically designed for Telia's Finland and Sweden operations. It is built on SevOne NMS (Network Management System) and integrated with Noora's custom components. SevOneDDC provides real-time monitoring of network devices, advanced cluster management capabilities, and sophisticated alert notification systems. The platform ensures high availability, network reliability, and comprehensive performance monitoring across Telia's critical infrastructure.

Q2. What are the main components of SevOneDDC architecture?
A2. SevOneDDC architecture consists of:
   - Distributed monitoring nodes for data collection
   - Centralized management interfaces for administration
   - Policy-based alert configuration systems
   - Cluster management functionality for load balancing
   - Database architecture for storing performance data
   - Integration capabilities with external systems

Q3. What is the objective of SevOneDDC?
A3. The primary objective of SevOneDDC is to pool devices by SNMP (Simple Network Management Protocol). It provides real-time monitoring, performance data collection, and alert management to ensure network reliability and performance across Telia's infrastructure.

=== DEVICE AND MONITORING MANAGEMENT ===

Q4. How does SevOneDDC collect performance data?
A4. SevOneDDC collects performance data through:
   - SNMP pooling of network devices
   - Performance evaluation by end users
   - CPU and memory monitoring handled by end users
   - Data collection frequency visible in device lists

Q5. What is a device in SevOneDDC and how is device discovery handled?
A5. In SevOneDDC:
   - Devices are typically added manually by end users
   - Operations team checks the status of SevOneDDC
   - User Manager tool is used for adding/removing devices
   - Device discovery is not automated; devices are added manually
   - Operations may assist end users with feedback and support

Q6. What is flow monitoring in SevOneDDC?
A6. Flow monitoring in SevOneDDC involves:
   - Tracking events and alerts from network devices
   - No direct action required on alerts (handled by end users)
   - Verification that alert timestamps match device activities
   - Ensuring the alerting system functions correctly

=== ALERT AND INCIDENT MANAGEMENT ===

Q7. What are the monitoring jobs in SevOneDDC and their criticality?
A7. Monitoring jobs in SevOneDDC:
   - No scheduled jobs or cron jobs
   - Monitoring involves observing alerts from the dashboard
   - Some alerts configured to send emails by users
   - Care must be taken not to delete any configurations
   - Criticality depends on the nature of the alert and its impact

Q8. What access is required for monitoring in SevOneDDC?
A8. Required access for monitoring includes:

   - User Provisioning: Creating and deactivating user accounts
   - Role Definition: Establishing user types with granular permissions
   - Access Control: Managing user access to clusters and views
   - Self-Service Capabilities: Enabling custom reports and dashboards
   - Administrative Functions: Handling system-wide configurations

Q9. What are alerts and thresholds in SevOneDDC?
A9. Alerts and thresholds in SevOneDDC:
   - Configured by end users
   - Alert Collection: Gathering device alerts from monitored elements
   - Timestamp Validation: Verifying accurate timestamping
   - Policy Application: Processing alerts according to policies
   - Destination Routing: Sending alerts to configured destinations
   - Delivery Verification: Ensuring proper alert delivery
   - Operations must be cautious with configuration management
