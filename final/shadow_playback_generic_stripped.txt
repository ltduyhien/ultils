Slide 15
--------------------------------------------------
Title: Daily Health Check Protocol at A Glance

Content Layout:
- Daily Health Check Protocol at A Glance
- Observed
- This protocol outlines the steps for performing a daily health check on the Application application, an instance of Vendor Application. The goal is to ensure the system is operational, alerts are functioning, capacity is stable, and server resources are monitored.
- Steps:
- 1. Login
- Log in to Application using Authentication System (Organization Central Authentication Directory).
- 2. Cluster Manager
- Navigate to the Cluster Manager.
- Verify the number of devices. Look for drastic changes that could affect capacity.
- Check the overall capacity. Ensure it has not changed significantly since the last check.
- Monitor specific clusters: c1, c2, p3, p4 (update)
- Note: Device mover processes are handled separately if capacity is exceeded.
- 3. Alerts
- Verify that alerts are flowing in.
- Check the timestamp of the topmost/latest alert to ensure it is recent.
- If no alerts are present, manually check the Policy Browser to confirm that alert rules are still active.

Slide 16
--------------------------------------------------
Title: Daily Health Check Protocol at A Glance (Continued)

Content Layout:
- Daily Health Check Protocol at A Glance (Continued)
- Observed
- 4. Device Managers
- Open the Device Manager.
- Check for any changes in devices or configurations.
- Add a column for "Date Added" and sort it to identify recent additions.
- If there is a large influx of new devices (e.g., 100 devices), notify the Resource Manager (RM) about the increased activity.
- 5. Reports
- Navigate to the Report Manager.
- Verify that favorite reports are accessible and their graphs are functioning correctly.
- 6. User Provisioning
- Check emails for user provisioning requests.
- Check User Management System for any new user provisioning requests. (User Management System could be automated with the requests, the requests could be fulfilled before getting resolved)
- Go to User Manager in Application, verify status of user account before doing any action
- Verify that user creation requests are legitimate (e.g., valid Organization email).
- Low number of user provisioning requests is typical, but large teams joining may require additional provisioning.

Slide 17
--------------------------------------------------
Title: Daily Health Check Protocol at A Glance (Continued)

Content Layout:
- Daily Health Check Protocol at A Glance (Continued)
- Observed
- 7. Check, Verify and Investigate
- Search for specific devices by name.
- Click on the device summary.
- Test device settings by performing a Monitoring Protocol walk function.
- Use the Monitoring Protocol OID Manager to verify device activity and Monitoring Protocol polling.
- Regularly check for admin error messages and investigate new alerts as needed.
- Use SSH to access the Application servers with users created specifically.
- Check disk space for critical partitions: /dev/sda2, /dev/sda3, and /dev/mapper/database.
- Verify server OS details using commands like `cat /etc/os-release`.
- 8. Escalation Procedures
- If issues are identified (e.g., missing data, alert failures, disk space issues), escalate to the Resource Manager (RM).
- For cluster issues, take screenshots (be careful with the confidentiality of the information, only use screenshot if really necessary, provide minimal data) and inform the RM.
- Focus on critical issues and escalate as needed.
- Follow the Organization process for creating any problem and incident ticket.
